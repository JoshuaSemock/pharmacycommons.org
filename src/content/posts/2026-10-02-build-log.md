**October 2nd, 2026
Joshua Semock, PharmD · pharmacycommons.org**

This document serves as the build log for Pharmacy Commons, detailing the technical progression from initial data models in July 2026 to the current deployed database and website. The rationale for the project is documented in the essay The Case for Shared Pharmaceutical Knowledge. This log focuses on technical implementation and architectural decisions.

## Core Architectural Principle

The system architecture operates on this processing sequence: ingestion, structuring, and readability. Each pharmaceutical record possess a human-readable interface, a uniform resource identifier, a primary key, a structured JSON payload for programmatic access, source provenance, and a version history. The platform acts as an interface to this Postgres SQL data layer, which is hosted on Supabase.

## July 3 – September 1: Initial Data Modeling

Development began with two months of data aggregation to evaluate the scope, publishers, and licensing terms of public drug databases. Initial sources included the FDA, NLM (RxNorm, DailyMed), NIH, Common Chemistry, and WHO (ATC classification).

Initial relational models were constructed in Excel worksheets. This segregated data types into distinct groups: active moieties, combination products, salts and esters, marketed formulations, and pharmacologic classes. This phase established the rules for distinguishing chemical entities, resolving combination components, and handling unmapped nomenclatures prior to database uploading. This served as the primary ETL (Extract, Transform, Load) source for the PostgreSQL database.

## September 2: Trademark Protection

A USPTO trademark search was conducted for "Pharmacy Commons". An Intent-to-Use (ITU) application under Class 42 software and database classifications is planned (but not yet funded) to secure the name and prevent private enclosure of theis open reference.

## Early September: Prototyping and Schema Revision

The first frontend utilized React, Vite, and Tailwind, rendering static JSON for twelve test drugs. The backend was   the data layer, initially loaded with 23 test entities (e.g., metformin, sertraline, lisinopril).

Early database iterations relied on name-hashing for primary identifiers, which was deprecated due to fragility during nomenclature corrections. The schema was revised to mandate that entity identifiers must remain stable and entirely independent of their mutable attributes.

## September 19: Database Foundation

The database was rebuilt with a formal relational schema.

* **Identifier Allocation (PCID):** Entities are assigned a Pharmacy Commons Identifier (PCID) from defined numeric blocks. Active moieties start at 1,000,001; combination products at 2,000,001; salts and esters at 3,000,001; marketed formulations at 4,000,001; and pharmacologic classes at 5,000,001. PCIDs are never reused. External registry keys (CAS, UNII, NDC, RxCUI, ATC) are stored as attributes to maintain system sovereignty.
* **Clinical Statements:** Clinical claims are modeled as subject–predicate–object triples (e.g., "metformin; has_indication; type_2_diabetes"). Each triple includes an evidence level and source citation using a controlled predicate vocabulary.
* **Write Controls:** Row-level security (RLS) is enforced across all tables. User submissions enter a moderation queue and require maintainer approval before production deployment.

The search index was optimized to return the base moiety, with specific salts, brands, and combinations nested hierarchically within the moiety's primary record. An initial batch import with 702 new moieties, isolated 14 stereoisomers/salts, flagged 157 rows was sent for manual review, and disqualified 634 rows lacking standard identifiers. This validated the necessity of checking for collisions prior to shipping and utilizied UNII/CAS strings for accurate duplicate resolution.

## September 22–23: Labels, Brands, Classes, and API Integration

* **Label Text:** The database currently indexes 52,571 DailyMed label documents comprising 2.33 million sections. Section text is fetched from openFDA upon initial request and subsequently cached. Ranking logic prioritizes single-ingredient, PLR-format, and manufacturer labels over repackager labels.
* **Brand Names:** Mapped via Drugs@FDA and 12,417 RxNorm brand rows. Single-ingredient brands map directly to the active moiety; multi-ingredient brands map to the specific combination.
* **Drug Classes:** Integrated RxClass, ClassyFire, and ChemOnt, yielding 4,981 classes and approximately 242,000 memberships. Each class renders on a dedicated page under `/classifications`.
* **Machine-Readable API:** A PostgreSQL function generates the payload for each PCID. Both the frontend and API consume this identical function to prevent data drift. Records are exposed as JSON and JSON-LD, featuring a defined schema, immutable version snapshots, and field-level change logs.
* **Routing:** `/id/PCID-n` provides a permanent redirect to the current entity URL. Retired PCIDs return a "gone" status.

## September 24–26: Compendium Lists, FDA Linking, and Performance

**Compendium Lists.** Curated collections were established under `/lists`, with each list assigned a unique PCID. Initial lists included:

* 247 most prescribed US drugs (averaged via AHRQ MEPS data, 2019–2023).
* 1,093 Notable Drugs categorized across 17 sub-lists.
* Georgia MPJE legend drugs and controlled substances.
* 226 Do Not Crush entries categorized by rationale (e.g., modified-release, hazardous).

Subsequent additions included Arrhythmia risk factors (173 drugs) and Anticholinergic Burden scores (205 drugs), bringing the total to 37 lists and 9,534 entries. Lists support sorting, filtering, CSV export, and side-by-side comparison. Mapping these lists required standardizing 3,150 source names against existing records, resulting in 27 newly minted PCIDs to address data gaps.

**FDA Product Linking.** Previously unlinked FDA data (12,261 products, 6,372 applications) was reconciled. Currently, 10,631 products and 5,161 applications are mapped to a PCID, generating 6,443 "has component" statements connecting formulations to moieties. Where FDA "active moiety" definitions conflict with clinical pharmacological standards, both definitions are retained.

**Performance Optimization.** Implementations included code-splitting, reducing the application icon payload from 1 MB to 6 KB, and converting the drug catalog to load asynchronously on user input rather than on initial page load. SEO additions included a sitemap, `robots.txt`, structured data, an `llms.txt` file for AI agents, and dynamic page titles.

## September 27–30: Clinical Tools and Governance

* **Medication Reconciliation:** A client-side tool was deployed to compile comprehensive medication lists without utilizing error-prone ISMP abbreviations. It calculates 24-hour maximum doses and exports to CSV, processing entirely within the local browser.
* **Days Supply Calculator:** Computes dispensing quantities and refill dates across varied dosage forms, factoring in priming, drops/mL, in-use limits, and whole-box dispensing.
* **Developer Interface:** A dedicated API console was deployed at `/developers`, featuring documentation, version comparison, and request templates. A `/v1/search` endpoint was added. The API requires no key and will be served via a Cloudflare proxy.
* **Legal and Licensing:** Terms of Use, Medical Information Disclaimer, Privacy Policy, and Data Provenance and Licensing Policy were enacted September 29. These render from static repository files to ensure alignment with official wording. Platform-generated content is licensed CC0 1.0; third-party data retains its source license.
* **References:** A centralized references table now tracks the 80 cited sources, supporting standard citation exports (AMA, APA, Vancouver, NLM, BibTeX).

## October 1–2: UI Redesign and Classifications

The UI was updated to a minimalist OKLCH-based design system, rendering pages as simulated single sheets of paper against a lichen photograph background. Typography was standardized to IBM Plex Sans Condensed. UI elements utilize embossed styling rather than colored outlines. Dark mode was implemented, and the header was consolidated to include search on every page.

Mobile optimizations (lazy loading the background and database library) improved local Lighthouse scores from 74 to \~95 and reduced largest contentful paint from 7.4s to \~2.5s.

**Classifications.** Drug classes were consolidated into a unified `/classifications` interface. A single query now searches WHO ATC, VA National Formulary, FDA EPC, and ChemOnt taxonomies. A database response bug limiting ATC and ChemOnt returns to 1,000 rows was identified and resolved.

## Project Roadmap

1. **Frontend Integration of FDA Links:** Update drug pages to display linked FDA products and approvals within the moiety hierarchy.
2. **API Proxy Deployment:** Finalize Cloudflare proxy routing for the API, publish the schema, and integrate list data into the endpoints.
3. **Chemical Structures:** Aggregate SMILES, InChI, and formulas for records containing a CAS number.
4. **Environmental Risk Metrics:** Deploy the ECOTOX data loader and publish the calculation methodology for risk quotients prior to frontend display.
5. **Community Moderation:** Develop the maintainer review interface for the community contribution queue.
6. **Trademark Finalization:** Execute the pending USPTO filing.
